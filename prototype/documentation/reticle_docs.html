RETICLE

RETICLE is a functional-genomics platform that harmonizes the world's published CRISPR screens (BioGRID ORCS) onto one comparable axis, then mines them to surface gene biology that isn't yet in the reference databases — a gene's phenotype fingerprint, the screens most like a given screen, data-driven gene–gene co-essentiality connections, and predicted-but-undiscovered gene functions — each cross-referenced against an offline multi-source knowledge base.

Design thesis. The point is discovery, not re-confirmation. If every connection RETICLE surfaced could already be looked up in STRING or GO, the work would be pointless — so the network channels are built purely from screen data and deliberately allowed to disagree with the curated databases, which are used only as an independent yardstick, never as an input to the edges.

What ships today

One Python http.server (web/app.py) serves three cross-linked pages. A shared top nav carries the current gene between them via ?gene=/?organism= URL params. All 14 API endpoints are live and each belongs to exactly one page.

Architecture & data flow

RETICLE is built in two halves: an offline build pipeline (the script/ directory) that transforms raw public data into query-ready tables, and an online serving layer (web/app.py) that reads those tables. Nothing is computed from raw screens at request time — every heavy aggregate is precomputed into a table or matrix.

The same SQL runs against both stores: queries use ? placeholders, translated to %s for Postgres. Which store answers depends on one environment variable and, for a few hot paths, on whether the local file is present — detailed next.

Serving backend

Every read handler in web/app.py reaches a database through one of four fetch helpers. The backend is chosen by a single switch and, for three helpers, a local-file preference.

The switch

USE_PG = bool(_ENV.get("AWS_DB_HOST"))            # app.py:83  — presence of AWS_DB_HOST in .env is the only switch
_PG_PARAMS = dict(host=…, dbname="reticle_biogrid",
                  options="-c search_path=reticle,public")   # search_path baked in at connect time

In the current checkout .env sets AWS_DB_HOST, so USE_PG is true and db_fetchall goes to RDS. But all five local .db files also exist, so the local-preferred helpers still read local sqlite — a single page request can mix RDS and local reads.

Connection pool

The server is a ThreadingHTTPServer — it spawns a fresh thread per request and discards it, so a thread-local connection is never reused and would pay the ~1.6 s RDS connect on every request. Instead a process-wide pool is shared across threads:

_pg_pool = ThreadedConnectionPool(4, 12, **_PG_PARAMS)   # app.py:123  minconn=4 warm, maxconn=12
# db_fetchall: getconn → autocommit → RealDictCursor → execute(sql.replace("?","%s")) → putconn
#              retries once, dropping a stale connection with putconn(con, close=True)

The pool is warmed at startup (a SELECT 1 in main()) so the first user request is already fast. (An in-code docstring at app.py:111 still says "2 warm connections"; the effective minconn is 4.)

Gene profile

GET /api/genelive

gene_payload() resolves a gene across every screen it appears in and splits its rows into fitness / stress / reporter ledgers by assay_domain — three domains that must never be pooled together because they measure different things.

Logic

  • Resolve & fetch — case variants of the symbol (no ortholog mapping); one SELECT joins harmonized_scores + screen_metadata + screen_metadata_curated, WHERE PERCENTILE_SCORE IS NOT NULL. If a symbol exists in two species, keep the better-represented one (max by row count).
  • Bucket by assay_domain; uncurated screens default to other, folded into reporter.
  • Fitness (domain_block, pooled axis): n, hit rate, median/mean/quartiles, a 26-bin histogram over [−1,1], and top-10 most-essential / most-advantageous screens. lean = essential if median < −0.15, advantageous if > +0.15, else mixed.
  • Stress (stress_ledger): per-condition, direction counted per PubMed paper (not per screen) as a majority sign of the harmonized score → resist / sensitise / mixed.
  • Reporter (reporter_ledger): "gene regulates {process}" facts from hit rows, controls dropped, direction deliberately omitted (gate-dependent and unreliable).

Screen similarity

GET /api/screen_similarlive

Given a query fitness screen, returns other human genome-wide fitness screens whose gene-level profile resembles it — ranked by pairwise-complete Pearson r on PC1-removed values, scored as a z ("σ") against the query's own background.

Algorithm (precomputed offline into RDS)

  • PC1 removal — the pan-essentiality axis carries 44.5% of variance and its gene loading correlates 0.998 with mean percentile; leaving it in makes any two fitness screens correlate ≈0.35 before biology, so it is projected out via SVD before correlating.
  • All-pairs pairwise-complete Pearson by mask algebra — each pair uses only genes both screens measured: n=mask·mask, Sxy=Zmᵀ·Zm, standard r formula. Pairs with overlap < 2000 shared genes are dropped (noise-dominated).
  • Background z at query time — z = (r − mean_r) / sd_r over the neighbour set: "is this screen more alike than the ≈0.35 baseline?" This σ is what the UI foregrounds.
  • same_study flag (shared PubMed id) + an exclude same study toggle, because the top matches are often the same publication (an unfixed batch confound).
RDS only screen_similarity (789K) · screen_sim_meta (962)
Rebuilt off the old 60 MB in-memory .npz (deleted from the app) into RDS by migrate_screen_similarity.py. Ranking is by raw r; background mean/sd are computed before the same-study filter, so the σ column is unaffected by the toggle.

External enrichment & "darkness"

GET /api/contextlive

ex.enrich(symbol, taxid) (from script/external_sources.py) returns a live-fetched, cached bundle: NCBI annotation, STRING partners, and a darkness score quantifying how under-studied a gene is.

Darkness formula

dark_pub = clamp01(1 − log10(pubs+1)/log10(1000))    # ≥1000 PubMed papers → 0
dark_go  = clamp01(1 − log10(go+1)/log10(50))       # ≥50 specific GO terms → 0
score    = round(10 · (0.6·dark_pub + 0.4·dark_go), 1)
band     = "dark" if score≥6.5 else "grey" if score≥3.5 else "bright"

Gene wiki (multi-source RAG)

GET /api/gene_wikilive

gene_wiki() assembles ~11 KB queries into one payload. No LLM — pure retrieval.

Resolution & assembly

  • Resolve (_kb_resolve): digits → kb_gene.gene_id; else kb_gene_alias exact then LOWER()-case, symbol-type aliases first. So "p53" or a retired GeneID still lands on current TP53.
  • identity (kb_gene) · aliases/orthologs · UniProt function/location/disease (inline PubMed cites stripped for display by _clean_uniprot) · GO ≤8 non-obsolete terms per namespace · STRING top-12 partners + a real sub-network · DepMap dependency class · screens (kb_screen_hit grouped by phenotype) · pathways (Reactome) · literature (PMID count).

In-screen score distribution

GET /api/gene_screen_distributionlive

Shows where the focal gene sits within the full distribution of every gene measured in the same screen, over its strongest FULL-coverage screens, with a toggle among the three stored normalizations.

  • Score toggle (score param): native→HARMONIZED_SCORE, percentile→PERCENTILE_SCORE (default), robustz→ROBUST_Z_SCORE.
  • Screen ranking: strongest FULL screens by absolute effect — ORDER BY ABS(PERCENTILE_SCORE) DESC, IS_HIT DESC, ABS(ROBUST_Z_SCORE) DESC (replaced an old ASC tautology that always opened "1st percentile").
  • Midrank ties: below = n_below + 0.5·n_tied — the standard fractional rank, correct on p-value-clipped screens where thousands of genes tie.
local reticle_master.db (≈50× faster)

Function prediction (undiscovered functions)

GET /api/gene_predictionslive

Predicts a gene's undiscovered GO Biological-Process functions by guilt-by-association — pooling votes from two annotation-independent neighbour layers, then keeping only terms the gene itself lacks.

Two neighbour layers, normalized then term-voted

  • STRING clean channels (_string_clean_neighbours): recombine only neighborhood/fusion/cooccurence/coexpression/experimental via p*=1−c/1000, clean=1−p. Deliberately excludes STRING's database + textmining channels — those encode curated GO/pathway knowledge and would make the prediction circular.
  • CRISPR co-essentiality (kb_coessential, orthogonal to STRING). Optional: silently degrades to STRING-only if the table is unbuilt.
  • Each layer normalized to its own max, merged additively; a term is a candidate only if 5 ≤ term_size ≤ 300, ≥2 supporting neighbours, and the gene lacks it. Score = sum of neighbour weights. Confidence high/moderate/tentative from #layers and #supporters.
kb.dbRDS reticle kb_string_edge · kb_coessential · kb_gene_go · kb_go_term · kb_gene(_alias)
Non-circularity is the whole point and is validated offline by a leave-one-out AUROC backtest (predict_backtest.py, not on the serving path): dropping the annotation-derived channels still recovers held-out functions above a random null.

Network page · network.html

Context-resolved co-essentiality network

GET /api/screen_netGET /api/net_contextslive · flagship

The flagship gene–gene network. Two genes are edged when their signed within-screen percentile profiles correlate across genome-wide screens — a purely data-driven co-essentiality signal. Served as a per-gene clustered neighborhood (seed + partners + partner–partner edges) colored by fitness lean, in a Cytoscape viewer.

Serve

  • Partners (screen_net): top-18 by edge strength, reciprocal-first-then-fallback — mutual-best partners if any exist, otherwise widen to one-directional and flag fellback (≈60% of genes have no reciprocal partner, so asking only for reciprocal blanked most of the network).
  • Node color (_net_fitness_lean): mean fitness percentile per gene → essential (<−0.15) / advantageous (>+0.15) / mixed. Served from the precomputed gene_fitness_lean table (was a 92 s live aggregate; now 0.06 s).
  • Contexts: human = all (pooled), mouse = mouse. An organism toggle switches tables; the mouse view is explicitly labeled exploratory.

Build (offline, compute_coessential.py)

  1. Genome-wide gate: only screens with coverage_type='FULL' AND n_genes ≥ 15000 (from net_screen) — FULL alone is not genome-wide.
  2. Node gates: hit_count ≥ 5 AND measured in ≥ 50% of screens AND hit_rate ≥ 0.02.
  3. Estimator (zscore): impute row-mean → center → project out PC1 (the pan-essential axis; its loading correlates 0.888 with hit rate; removing it lifted CORUM precision 42.8%→59.1%) → L2-normalize, so Z·Zᵀ is Pearson.
  4. Edges: top-25 partners with support ≥ 20 and r ≥ 0.15; the final threshold is set by a within-screen-shuffle null at FDR ≤ 0.05.
  5. Written to net_edge as (gene_a, gene_b, context='all', channel='coessential', strength, support, reciprocal).
RDS net_edge (109K) · net_edge_mouse (83K) · gene_fitness_lean local reticle_net(_mouse).db
Three distinct "co-essentiality" artifacts exist — don't confuse them: net_edge (this, the PC1-removed thresholded flagship, on the Network page); coess_{taxid}.npz (dense pooled cosine, on Explore's /api/coessential); and the Fisher hit_only_connection (below, not wired). The mouse build uses a reduced algorithm (no PC1, min-screens 40) and is throwaway/exploratory.

Data pipelines · offline, no UI

Harmonization

harmonize_scores.pypipeline

The numeric foundation. Converts heterogeneous BioGRID-ORCS score columns onto four stored scores, writing harmonized_scores + screen_metadata (rebuilt from scratch each run).

ColumnDefinition
HARMONIZED_SCOREs_raw · perturbation_mult on one biological axis: + = knockout advantageous/enriched, − = essential/depletes. CRISPRa/activation screens are sign-flipped (mult=−1). s_raw priority: directional pair > single directional column > significance×selection-sign. A frozen LLM directionality override wins when present.
PERCENTILE_SCORERank-normalized within each screen to [−1,1]: 2·(rank/max_rank)−1 over measured genes only. This is the cross-screen-comparable axis everything downstream uses.
ROBUST_Z_SCORE(v − median) / (MAD·1.4826), std fallback when MAD=0.
IS_HIT1 iff the screen's HIT field is "YES".

COVERAGE_TYPE = HIT_ONLY if the full score set isn't available, else FULL — the data-availability flag the genome-wide gate later refines with an n_genes cut.

Assay-domain stratification & directionality

screen_metadata_curatedpipeline

Two independent "direction" concepts, often confused — kept in different columns by different scripts.

(a) Assay domain — which pool a screen belongs to

A rule-first, LLM-fallback pipeline tags every screen fitness / stress / reporter / other, plus three condition facets, into screen_metadata_curated. Initial tag is keyed off BioGRID PHENOTYPE; deterministic facet rules (from EXPERIMENTAL_SETUP/condition text) refine it; the long tail is resolved by an LLM at confidence ≥ 0.7. The app pools/correlates only within a domain — this is what stops a conditional-stress screen from diluting the clean fitness essentiality axis.

(b) Directionality — the sign of the phenotype

For screens harmonization couldn't sign, directionality_mapper.py asks an LLM to place them on the unified LoF axis (+1 advantageous, −1 essential), frozen into directionality_overrides.json (auto=71, needs_review=29, binary_only=11). apply_directionality.py / fix_directionality.py then re-sign harmonized_scores, with an essential-gene anchor: a panel of core-essential genes (POLR2A, RPL3, PSMA1, …) must land on the negative end in a viability knockout screen, else the sign is rejected/flipped.

This realizes the memory rule "LLM assigns directionality on ambiguous screens, not control_comparison; frozen overrides.json + essential-gene anchor." The essential anchor in fix_directionality.py runs over fitness KO screens only — stress is explicitly excluded.

Fisher co-hit channel (Channel 2)

compute_hit_only.pybuilt · not wired

An alternative connection channel: instead of correlating continuous profiles, it tests whether two genes are called hits together more often than their individual hit rates predict — a one-sided Fisher / hypergeometric upper-tail test.

n  = M·Mᵀ   # co-measured screens (Fisher population)     — np.rint required:
a  = H·Hᵀ   # co-hit overlap                                  float matmul drifts off
ri = H·Mᵀ ; rj = M·Hᵀ   # each gene's hits in the other's screens   integers → hypergeom
p  = hypergeom.sf(a−1, n, ri, rj)          # then BH-FDR ≤ 0.05        returns NaN silently

Why Fisher not Pearson: range restriction kills Pearson variance on hit-saturated genes (PSMB5/PSMB4 r 0.667→0.046 vs Fisher p=8.8e-250), and Fisher folds evidence volume into the p-value so no support floor is needed.
